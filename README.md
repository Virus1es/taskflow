## 1. Описание и архитектура

TaskFlow — учебное веб-приложение для управления списком дел. Реализованы создание, просмотр, изменение названия, 
отметка выполнения и удаление задач. Данные сохраняются в PostgreSQL и доступны после перезапуска приложения.

Сервер разработан на Node.js и Express, интерфейс — на HTML, CSS и нативном JavaScript. Для работы с PostgreSQL 
используется библиотека `pg`. Архитектура разделена на HTTP-маршруты, middleware авторизации, валидацию запросов и 
слой доступа к данным.

Приложение размещено на Render с публичным HTTPS-адресом. PostgreSQL размещена на Aiven. GitHub Actions используется 
для проверки приложения интеграционными тестами; автоматический деплой в Yandex Cloud отключён.

## 2. HTTP API и авторизация

Все маршруты `/api/` требуют заголовок `Authorization: Bearer <token>`. Применяется статический токен из серверной 
переменной `API_TOKEN`, а не JWT. Токен вводится пользователем через интерфейс и не включён в исходный код.

Некорректные запросы возвращают `400`, отсутствие или неверность токена — `401`, ненайденные задачи — `404`, ошибки 
доступа к БД — `503`.

| Метод | Маршрут | Назначение |
|---|---|---|
| GET | `/login/` | Публичное получение логина Moodle |
| GET | `/api/author/` | Логин и ФИО автора |
| POST | `/api/tasks/` | Создание задачи |
| GET | `/api/tasks/?runId=...` | Получение списка задач |
| GET | `/api/tasks/:id/` | Получение одной задачи |
| PATCH | `/api/tasks/:id/` | Изменение задачи |
| DELETE | `/api/tasks/:id/` | Удаление задачи |

## 3. Структура PostgreSQL

Данные хранятся в таблице `public.tasks`. Идентификатор, владелец, дата создания и начальное состояние задачи 
устанавливаются сервером. Названия полей API используют camelCase, физические столбцы PostgreSQL — snake_case.

| Поле API | Столбец БД | Тип |
|---|---|---|
| `id` | `id` | UUID, PRIMARY KEY |
| `ownerLogin` | `owner_login` | VARCHAR(100) |
| `title` | `title` | VARCHAR(200) |
| `done` | `done` | BOOLEAN |
| `runId` | `run_id` | VARCHAR(64) |
| `createdAt` | `created_at` | TIMESTAMPTZ |

SQL-схема расположена в `db/init.sql`.

В базе создана обязательная задача **«Итоговая работа 24.10.2026: troan»** с `runId="manual"`.

## 4. Сравнение размещения PostgreSQL

Проверка условий: **19.11.2026**.

| Площадка | Тариф и ограничения | Результат рассмотрения |
|---|---|---|
| **Aiven** | Free без фиксированного срока: 1 ГБ диска, 1 ГБ RAM, 1 CPU, максимум 20 соединений; отсутствует встроенный connection pooling | Создана PostgreSQL 18.7; подключение Render работает; прямой доступ проверяющего и чтение данных подтверждены |

| **Yandex Managed PostgreSQL** | Платное размещение; стоимость зависит от вычислительных ресурсов, диска, резервных копий и сетевого трафика | Управляемый PostgreSQL не развёртывался. Отдельно предпринимались попытки размещения приложения в Serverless Containers |

### Факультетский сервер Helios

Проверен факультетский сервер `helios.cs.ifmo.ru`: SSH-доступ успешен, операционная система — FreeBSD 14.5-STABLE. 
В окружении доступен клиент PostgreSQL 18.3, однако команда `node` не найдена.

Кафедральный PostgreSQL на `pg.cs.ifmo.ru:5432` принимает подключения, но попытка авторизации с университетской учётной 
записью завершилась ошибкой `password authentication failed`. Права на создание таблиц не подтверждены.

Проверка соединения с Aiven на порту `13478` завершилась тайм-аутом. Возможность публикации Node.js-приложения через 
HTTPS не исследовалась. Поэтому Helios рассмотрен как альтернативная площадка, но для итогового развёртывания выбраны 
Render и Aiven.

### Обоснование выбора

Для хранения данных выбран Aiven Free, поскольку он позволяет бесплатно использовать PostgreSQL и выделить проверяющему 
отдельного пользователя. Render обеспечивает публичное HTTPS-размещение Express-приложения. Развёртывание на Yandex 
Serverless Containers не удалось довести до работоспособного состояния даже при диагностических проверках, поэтому 
итоговая версия перенесена на Render.

## 5. Установка и запуск

Необходимы Node.js 22, npm и доступная PostgreSQL. Для локальной разработки предусмотрен Docker Compose.

Клонирование и установка зависимостей:

```bash
git clone https://github.com/Virus1es/taskflow.git
cd taskflow
npm ci
```

Создайте `.env` по образцу `.env.example` и укажите:

```dotenv
DATABASE_URL=postgresql://USER:PASSWORD@HOST:PORT/DATABASE?sslmode=require
API_TOKEN=your-secret-token
MOODLE_LOGIN=troan
MOODLE_FULL_NAME='Вадим Якубенко'
PORT=3000
```

Переменные содержат демонстрационные значения. Реальные пароли и токены не должны попадать в Git.

Для запуска локальной PostgreSQL:

```bash
docker compose up -d
```

При необходимости примените схему из `db/init.sql` к выбранной базе. Затем запустите приложение:

```bash
npm start
```

Локальный адрес: `http://localhost:3000/`.

Интеграционные тесты выполняются командой:

```bash
npm test
```

Перед запуском тестов должен работать HTTP-сервер с доступом к тестовой PostgreSQL. В GitHub Actions для CI 
используется отдельная PostgreSQL. Подготовлены 11 интеграционных тестов.

## 6. Проверка и доступ к базе

В Aiven предусмотрены два пользователя: `taskflow_app` для приложения и `taskflow_reviewer` для преподавателя.

Для `taskflow_reviewer` подтверждены права `SELECT`, `INSERT`, `UPDATE`, `DELETE` на `public.tasks`, при этом право 
`TRUNCATE` отсутствует. Успешно выполнено прямое подключение через `psql 18.7` с TLS 1.3 и чтение обязательной задачи 
из БД без SSH-туннеля.

Проверяющему предоставляются отдельные реквизиты подключения к PostgreSQL и Bearer-токен приложения личным сообщением 
в Moodle. Секреты не публикуются в репозитории и сообщении форума.
